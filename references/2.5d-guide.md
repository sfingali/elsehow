# Elsehow 2.5D Guide: Layered Worlds and Thread

The 2.5D atlas is a **projection of the same semantic graph**, not a new timeline model. World identity, traveller movement, instance fate, and evidence remain separate layers. Layout and camera settings belong to the renderer, never the abstract story JSON.

## 1. THE 3D MODEL

### Coordinate frame

Use narrow, shallow world strips in an orthographically projected scene:

- **X — world position:** categorical columns inherited from the 2D layout; distance has no semantic meaning.
- **Y — story order:** increases from the labelled far/start edge toward the near/end edge.
- **Z — exploded separation:** separates strips and connector layers for readability. It is neither another time axis nor a measure of reality, probability, or importance.

A world’s rail lies along the centre of its strip at `(x_world, y, z_world)`. Events are anchors on that centreline. Repeated visits reuse the same strip.

Use **ordinal bands**, not numeric order differences:

```text
orders = sorted(unique(non-null event.order))
band[order] = index in orders
y(event) = top_margin + band[event.order] * band_spacing
```

Equal orders share a band without asserting physical simultaneity. Put null-order events on a separate **“Order unspecified”** shelf; do not connect them by an invented chronological rail.

### Exact orthographic projection

Choose a camera tilted **30° from overhead**, with **12° in-plane yaw**. This gives shallow depth without vanishing-point distortion.

```text
θ = tilt from overhead; default 30°
φ = in-plane yaw; default 12°
k = uniform scene scale
ox, oy = screen translation

u = cos(φ)*x - sin(φ)*y
v = sin(φ)*x + cos(φ)*y

screen_x = ox + k*u
screen_y = oy + k*(cos(θ)*v - sin(θ)*z)

camera_depth = sin(θ)*v + cos(θ)*z
# Larger camera_depth is nearer the viewer.
# Paint farther surface fragments first.

Python:
def project(x, y, z, theta, phi, scale, ox, oy):
    u = math.cos(phi)*x - math.sin(phi)*y
    v = math.sin(phi)*x + math.cos(phi)*y
    return (
        ox + scale*u,
        oy + scale*(math.cos(theta)*v - math.sin(theta)*z)
    )
```

For geometry entirely on one plane `z=h`, SVG can use:

```text
<g transform="matrix(a b c d e f)">

a =  k*cos(φ)
b =  k*cos(θ)*sin(φ)
c = -k*sin(φ)
d =  k*cos(θ)*cos(φ)
e =  ox
f =  oy - k*sin(θ)*h

At θ=30°, φ=12°, k=1:
matrix(0.978148 0.180057 -0.207912 0.847101 ox (oy-0.5*h))
```

Compute the numeric last argument before emitting SVG. A single matrix cannot represent several heights or a cable whose height changes: use separate plane groups or project its vertices in Python.

Practical starting dimensions, in scene units:

- Strip width: 28; world-centre gap: 160–220; order-band spacing: 54.
- Strip thickness: 2, purely decorative; omit side faces in the first implementation.
- Assign stable heights across a shallow 0–24 range using layout index, not ancestry or origin.
- Keep transfer lift around 12–20 units and thread lift around 2 units.
- Maintain readable labels in screen units; enlarge the canvas rather than shrinking text.

Include: **“Story order → near edge · Exploded separation is layout only.”**

## 2. ELEMENT MAPPING

| Existing element | 2.5D representation and attachment rule |
|---|---|
| World rail | Thin neutral centreline on a narrow matte strip. Keep persistent world ID and label; strips never fuse at crossings. |
| Initial origin | Square header labelled **“Initial in model.”** It does not declare the beginning of the universe. |
| Born origin | Strip starts at the declared birth junction’s story band, with a fork seam. Its first outcome event may occupy a later band. No pre-birth strip. |
| Preexisting origin | Strip enters through an open continuation mark at the scene boundary; label **“Already existed.”** Arrival does not start it. |
| Unknown origin | Freestanding `?` tab, separate from the first known event; no invented parent or birth seam. |
| Off-chart ancestry | Outward-facing ancestry tab. Preserve literal starred IDs and add **“Ancestry off-chart.”** |
| Start / split / outcome | Shallow square / amber circular / tine-labelled pins at exact anchors. Keep their original shape distinctions. |
| Entry / exit | Inward/outward arrow-notches touching event anchors. |
| Anchor / cutoff | Diamond pin / transverse bracket with **“Chart stops here.”** Cutoff is not universe destruction. |
| Gate entry / exit | Portal brackets with literal sign and entry/exit labels. No paired gate or connector without a supplied relationship. |
| Split edge | Thin bridge from split anchor to outcome anchor; `+` solid, `−` dashed. Label both explicitly. Neither sign inherently means death or selected route. |
| Transfer | Directed elevated elbow cable, with transfer ID, traveller, and B/M/C/S badge. Ends descend to and visibly touch the actual anchors. |
| Traveller thread | Strong narrow ribbon along supplied visits, nearly flush with strips; follows explicitly linked split/transfer geometry between visits. |
| Fate | Screen-facing upright flag attached to the named instance and world: `× Dead`, `● Alive`, `? Unknown`, `∅ Nonexistent`. |
| Segment / beat | Margin bracket between supplied endpoints / screen-facing callout at supplied order. Unsupported placement fields remain in the inspector. |
| Labels | Screen-facing billboards with leaders where displaced. Do not skew, rotate, or shrink typography with strip perspective. |
| Citation | Numbered screen-facing evidence tab; expanded card contains source, page, scene, locator, kind, and actual status. |
| Visit strip / metadata | Flat screen-space footer and header, outside the projected tray. Show visit numbers, namespace, profile interpretation, and axis. |

### Connector construction

Build transfer elbows in scene space, then project every vertex. Do not apply SVG `H`/`V` commands to projected endpoints.

For source `A=(xa,ya,za)` and destination `B=(xb,yb,zb)`:

```text
h = max(za, zb) + cable_lift
g = allocated routing-gutter X coordinate

cable vertices:
A → (xa,ya,h) → (g,ya,h) → (g,yb,h) → (xb,yb,h) → B
```

Remove duplicate vertices. Allocate distinct gutters for crowded cables. Same-world transfers use a side gutter and return to the same strip; they never create a duplicate world.

Use a solid capsule for body, distinct lettered memory/consciousness tokens, and a pulse marker for signal. Preserve unknown mechanism strings verbatim rather than reducing them to an unexplained dot.

### Semantic attachment details

- Same-world split outcomes continue the strip; born outcomes begin a separate strip.
- Keep structural tines visible beside the selected ribbon. The world forks; the traveller thread need not.
- Use `route.links` and visit `passes`; never join consecutive visits simply because they are adjacent in the array.
- Missing transition records produce labelled gaps. A zero-length visit is a numbered point stop.
- A fate referencing another world’s event stays attached to the **fate’s world**, with an explicit reference leader.
- If that reference predates the target strip’s birth, use an outboard flag referencing the birth seam; do not draw a pre-birth rail.
- Death never cuts a strip. A shortened outcome strip ends with **“Further detail not supplied”**, not a death-shaped endpoint.
- Evidence typography distinguishes **Order 10 · Scene 10 · p.4**. Missing citation means **“No citation supplied.”**

## 3. DEPTH & OCCLUSION

### Visibility contract

Every overview must expose each world identity, supplied split outcome, transfer destination, fate, and route gap—or a visible, explicitly labelled callout for it. Essential facts must not require hover.

Use this collision-resolution sequence:

1. Reserve screen-space boxes for event pins, fate flags, mechanism badges, and evidence tabs.
2. Move labels into side gutters with leaders.
3. Separate overlapping cable routes and add endpoint halos.
4. Increase world spacing or shallow height separation without changing world order.
5. Cut away decorative strip faces beneath obscured connectors.
6. Expand the canvas or supply a labelled detail inset; do not silently hide topology.

A crossing has no junction marker. At ambiguous crossings, give the foreground edge a small background halo and show a short break in the edge behind it; label any longer hidden section. Do not use a bridge or crossing as evidence of connection.

Keep shadows restrained and optional. Do not fade distant worlds enough to suggest nonexistence or “inactive reality.” Focus dimming is temporary and explicitly labelled as a display filter.

### Camera and interaction bounds

- Allow tilt from 20–35° and yaw from −15° to +15°; no underside view, roll, or reversal of story-order reading.
- Recompute projected anchors, collisions, and bounds after camera changes.
- Separation controls change only renderer heights and spacing.
- Isolation keeps a world/relationship inventory and boundary stubs labelled with hidden destinations.
- Folding preserves outcome IDs, connection counts, and fate summaries.
- Provide **Reset camera**, **Show all**, and **Exact 2D atlas** controls.

**WAIF check:** J− must remain selectable after the local native-instance death and before Ben’s later arrival. T−, M−, and C− remain visible as compact outcome strips. BEN and W occupy separate trays; no camera operation may imply a connection between them.

## 4. PROFILE PARAMETERS IN 2.5D

Expanded parameters constrain presentation; explicit records still determine every strip, edge, and annotation.

| Parameter or case | Required treatment |
|---|---|
| `history_model=universes` | Distinct world strips. State coexistence separately; depth alone makes no coexistence claim. |
| `history_model=revisions` | Supplied revision states become a ledger or attached archive leaves within the modeled identity, not additional universe strips. |
| `branching=overwrite` | Label supported transitions **“Supersedes.”** Preserve recorded prior states as **“Superseded record—not coexisting world.”** |
| `history_model=iterations` | Repeat bands on one strip, only where repetition is recorded. No world per loop; no invented sequence from a loop count or film title. |
| `branching=branch` | Retain all recorded outcomes after departure and death. |
| `branching=undeclared` | Neutral relationship labels; explicit split records may still be drawn, but no inferred fork or overwrite. |
| `coexistence=single_active` | Use active/archive chips only where activation is known. Otherwise state **“Activation unspecified.”** |
| `coexistence=undeclared` | Header says **“Coexistence unspecified.”** No depth-based active/inactive distinction. |
| `genealogy=bootstrap_cycles` | Separate causal/genealogical inset for explicit relationships. A flag alone produces a note, not a self-loop. Main axis remains story order. |
| Signal transfer | Labelled pulse cable. Do not extend a body-occupancy ribbon over it; animate only the represented signal. |
| `joined_worlds`, `time_mechanics`, `turnstiles` | Interpretation chips and allowed vocabulary. Origins and actual transfer records control individual marks; flag contradictions. |
| Multiple travellers | Shared world strips with colour-plus-label threads or synchronized small multiples. Never a world per traveller or visit. |
| `axis=world_time` | Unless documented enrichment supplies coordinates, show **“World-time data unavailable—showing story order.”** |
| Validation / merges | Separate interpretation-status banner and supplied merge count. Flag forbidden-merge contradictions; never invent merge locations. |

Keep assumptions in a persistent panel, not as new geometry. Show evidence status independently of interpretation status; fixture citations are not screenplay proof. Expose unsupported loose-schema content in the inspector.

## 5. IMPLEMENTATION PATH

### Refactor before adding perspective

The supplied `render.py` emits SVG directly from semantic records. Introduce shared stages:

```text
abstract JSON
  → validated record index
  → semantic drawable records
  → canonical 2D layout and event anchors
  → 2D adapter OR shallow-scene adapter
  → projection, screen-space annotation layout
  → SVG + accessible ledger
```

Each drawable should retain namespace, source record reference, role, geometry, and style. Use namespace-qualified stable IDs; preserve literal IDs such as `J-` and `*2` as text and metadata.

### Correct current shortcuts in both views

Before calling the new view semantically equivalent:

- Replace numeric-order spacing with ordinal bands; render null-order events and worlds without ordered events.
- Centralize event anchors. Current node offsets can disagree with edge/fate positions; group equal-order collisions by **world and order**, not globally.
- Stop resolving unknown worlds to the first column. Report broken references with unattached diagnostic cards.
- Use declared birth references rather than the earliest event as the birth location; flag conflicting parent/event/outcome records.
- Replace automatic visit-to-visit polylines with explicitly supported transitions.
- Correct the legend: `+`/`−` are outcome signs, not universal follow/death labels.
- Attach cross-world fates correctly, implement evidence tabs/status, and expose profile interpretation rather than merely printing parameters.
- Default to the existing earliest-world-rightmost arrangement; make alternative ordering an explicit, stable renderer option.

### SVG rendering strategy

**Recommended first version:** Python projection, flat strip polygons, projected cable polylines, and untransformed SVG text.

A matrix group is cheaper for each constant-height strip’s surface marks. It is unsuitable for billboards and variable-height cables. Do not transform the entire existing SVG: that would distort text and still provide no real separation.

Paint in controlled passes:

1. Background, graph trays, and optional shadows.
2. Strip surfaces and side faces, far to near.
3. Centre rails, repeat bands, archive annotations, structural bridges.
4. Transfer cable segments and thin thread ribbons.
5. Event anchors, endpoint rings, arrowheads, and selection outlines.
6. Screen-facing labels, mechanism badges, fate flags, evidence tabs.
7. Headers, legend, visit strip, diagnostics, and focus controls.

Within surface passes, use camera depth. Average-depth sorting is acceptable only for nonintersecting shallow surfaces. Split overlapping fragments or use explicit cutaways when ordering is ambiguous. Semantic overlays deliberately take priority over physical realism.

### Delivery steps and cost

1. Add proposed `--view 2d|2.5d`, camera preset, and separation settings; leave format selection unchanged.
2. Build shared indexes, anchors, diagnostics, and ordinal layout; add semantic regression tests.
3. Add `project()`, strip polygons, and connector vertex projection.
4. Add billboards and deterministic collision placement.
5. Compute bounds from projected geometry **and** label boxes; stack namespace trays using those bounds.
6. Add HTML controls that reproject geometry and preserve selection.
7. Add archive/repeat detail, filtering, and optional animation only after static correctness.

**Cheap:** shallow strips, orthographic projection, SVG paths, fixed-size badges, static depth presets.  
**Moderate:** label placement, cable routing, keyboard interaction, synchronized selection.  
**Expensive:** unrestricted orbit, physically correct intersecting surfaces, live depth sorting, animated ribbon meshes. None is necessary for a useful first release.

Test WAIF’s eight BEN worlds, three consciousness transfers, preserved J− destination, cross-world fate leader, separate W tray, and final W point stop. Also test missing links, signal-only movement, sparse orders, null orders, conflicting birth records, and repeated local IDs across namespaces.

## 6. EXPORT

- **SVG master:** save a projected vector still with searchable billboard text, stable semantic groups, complete legend, and accessible event/route ledger. The exact 2D SVG remains the topology-reading companion.
- **PNG:** rasterize the same SVG at the requested resolution; include the axis/depth disclaimer, profile interpretation, and visible filter state. Supply the ledger/evidence appendix alongside it.
- **HTML:** embed the source-derived scene data and controls for bounded orbit, separation, isolation, evidence inspection, and synchronized 2D selection. Provide keyboard navigation, visible focus, and reduced-motion support.
- **Print/static fallback:** use a tested camera preset and expanded critical callouts; never depend on hover, animation, or hidden inspectors.
- **Animation, if added:** move the appropriate traveller or signal token through supplied visits and links. Do not rewind, erase, or replace world strips to dramatize travel.

The return to 2D uses the **same canonical layout**, not an approximate inverse of the screenshot:

```text
2D:   canonical world X + ordinal band Y
2.5D: those same anchors + renderer-only Z + camera projection
```

Store camera, folding, and selection in renderer-side settings. “Exact 2D” restores canonical geometry and labels while retaining record selection. Empty or unresolved links remain unresolved in both views.

## 7. PITFALLS — THE TOP FIVE

1. **Making depth semantic.** Height, shadows, distance, and focus dimming must not mean later, truer, more probable, or the only surviving universe.
2. **Conflating world, traveller, and instance.** A native counterpart’s death cannot erase its strip or terminate another traveller’s thread; consciousness transfer is not a moving body.
3. **Inventing connectivity.** Crossings are not junctions; consecutive visits are not sufficient links; profiles do not manufacture gates, revisions, merges, or bootstrap cycles.
4. **Letting perspective hide facts.** Preserve every tine, fate, and destination through callouts, separation, cutaways, or labelled detail views—not hover-only recovery.
5. **Treating the current renderer’s shortcuts as the specification.** Correct sign meanings, order spacing, birth placement, route gaps, namespace isolation, and evidence handling in the shared model before lifting the atlas.
